## Executive Summary

Physical and digital evidence gathered by distributed Internet of Things (IoT) devices—such as security cameras, environmental sensors, and smart access nodes—is inherently susceptible to retrospective manipulation, timestamp tampering, and chain-of-custody disputes.

**ChainForensics** was developed in the laboratory as a proof-of-concept forensic pipeline. By pairing embedded microcontrollers (ESP32) and edge gateways (Raspberry Pi) with an immutable Solidity smart contract registry (`EvidenceRegistry.sol`), the system establishes non-repudiation and verifiable timestamps at the point of data capture.

This technical case study documents the hardware choices, message broker architecture, smart contract design, and experimental benchmarks evaluated on a local Ethereum testbed.

## The Forensic Problem

In traditional IoT telemetry collection:
1. **Unauthenticated Transport:** Sensor packets sent over unencrypted local networks can be intercepted and modified via Man-in-the-Middle (MitM) vectors.
2. **Post-Incident Tampering:** Database logs on centralized servers can be retrospectively edited by compromised administrator accounts.
3. **Chain-of-Custody Failure:** Without cryptographic proof of origin and capture time, evidentiary weight in forensic audits is significantly diminished.

Storing full sensor telemetry directly on a public blockchain is cost-prohibitive and presents severe privacy issues. The architecture required a hybrid design: **perform local telemetry collection off-chain, compute cryptographic digests at the edge, and notarize only the verifiable root on-chain.**

## System Architecture

The pipeline consists of three decoupled operational tiers:

### 1. Edge & Sensor Tier (ESP32)
- Microcontrollers interface with environmental and security sensors.
- Hardware cryptographic accelerators on the ESP32 compute a SHA-256 digest of each incoming telemetry batch.
- Payloads are signed with device keys and transmitted via authenticated MQTT to the local edge gateway.

### 2. Message Broker & Gateway Tier (Raspberry Pi & Aedes)
- A lightweight Node.js MQTT broker (**Aedes**) runs on the gateway node.
- Client authentication hooks validate device credentials before accepting incoming telemetry streams.
- The gateway aggregates and buffers hash entries to withstand intermittent wide-area network disconnects without data loss.

### 3. Verification & Registry Tier (Hardhat & Solidity)
- An EVM-compatible smart contract (`EvidenceRegistry.sol`) maintains append-only records containing:
  - `bytes32 evidenceHash`: SHA-256 digest of the telemetry packet.
  - `uint256 timestamp`: Block timestamp of registration.
  - `string deviceId`: Identifier of the originating sensor node.
- Provides public constant view functions (`verifyEvidence`) allowing investigators to verify any raw evidence file against on-chain records.

## Smart Contract Design: EvidenceRegistry.sol

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract EvidenceRegistry {
    struct EvidenceRecord {
        bytes32 evidenceHash;
        uint256 timestamp;
        string deviceId;
        address registeredBy;
    }

    mapping(bytes32 => EvidenceRecord) private _records;
    event EvidenceLogged(bytes32 indexed evidenceHash, uint256 timestamp, string deviceId);

    error EvidenceAlreadyRegistered(bytes32 evidenceHash);

    function recordEvidence(bytes32 hash, string calldata deviceId) external {
        if (_records[hash].timestamp != 0) {
            revert EvidenceAlreadyRegistered(hash);
        }

        _records[hash] = EvidenceRecord({
            evidenceHash: hash,
            timestamp: block.timestamp,
            deviceId: deviceId,
            registeredBy: msg.sender
        });

        emit EvidenceLogged(hash, block.timestamp, deviceId);
    }

    function verifyEvidence(bytes32 hash) external view returns (bool exists, uint256 timestamp, string memory deviceId) {
        EvidenceRecord memory record = _records[hash];
        if (record.timestamp == 0) {
            return (false, 0, "");
        }
        return (true, record.timestamp, record.deviceId);
    }
}
```

## Security & Architectural Decisions

- **Zero PII On-Chain:** Only irreversible SHA-256 digests and anonymous device IDs are committed to the blockchain, eliminating privacy leaks.
- **Append-Only Immutability:** Once logged, evidence records cannot be modified or purged by any network participant.
- **Fail-Safe Offline Buffering:** If the Ethereum connection drops, the Aedes gateway buffers pending evidence entries locally in SQLite until network restoration.

## Testbed Validation & Benchmarks

The system was evaluated under laboratory conditions using a simulated network of 10 virtual ESP32 nodes and a physical ESP32 DevKit:

- **Edge Hashing Latency:** Computed 1KB payload SHA-256 digests on ESP32 hardware in ~4.2 ms.
- **Smart Contract Execution:** Single record registration consumed **44,210 gas** on the local Hardhat test network.
- **Tamper Detection Accuracy:** Tested with 200 deliberate 1-bit file alterations; 100% of altered files failed hash verification against the ledger.
